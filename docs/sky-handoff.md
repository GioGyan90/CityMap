## 积累的方法论

1. **整体规划 → 独立原件 → 组合 → 实际场景多角度检查 → 修正 → 复查。** 先弄清用途、视觉层次、尺寸、位置和光照关系，再制作；复杂元素拆成可单独检查的原件。不要只根据顶视图、示意图或构建通过判断完成。
2. 场景美术保持明亮清爽的日式手游感和海滨度假氛围；C 方案采用蓝绿主体与紫、洋红等有节制的撞色。应区分主色、辅助色和局部点缀，不让天空喧宾夺主或使建筑全部偏色。
3. 先检查原件的支撑、边界、法线和连接，再看组合；天空要特别关注密度体边界、半透明排序、移动边界淡入淡出、云影与实际云位及日照方向一致，以及高楼和云层的空间关系。若调整共享素材，检查所有复用位置。
4. 光照应随时间连续过渡：白天、日出、日落、余晖、深夜及跨午夜；避免太阳落山后仍从地下照亮城市，避免墙体、屋顶被当成发光窗。海水、地平线雾、云、天空和建筑共同审视。
5. 固定种子、参数化结构及明确性能预算；云动画与昼夜时间、全局动画暂停以及资产查看器的控制应保持各自原有语义。透明层、着色器循环、纹理和设备帧率需要关注，不能只比较生成时间或网格数量。
6. 检查正、侧、背、斜视及必要低角度；在真实尺度及完整城市里复查，不只看独立样件。对发现的问题先修复，再补充能覆盖该问题的必要回归。保留同机位前后对照和实际观察时段，清楚标注渲染方式。
7. 测试和构建执行 `npm test`、`npm run build`、`git diff --check`；按任务增加着色器编译、昼夜连续性、暂停恢复和性能检查。生产构建含启动依赖检查，不要合并有初始化副作用的启动模块。
8. 发布使用现有 `.github/workflows/deploy.yml` 的 Actions → Vite dist → Pages，检查对应提交的 build 与 deploy；线上资源匹配及真实浏览器视觉检查分别报告，不把其中一项当成其他项的证明。
