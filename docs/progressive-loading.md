# 可操作灰模首屏与渐进恢复

2026-10-28（北京时间）。基于远程 main `ca922b788c42e3dfa792d2e1c13d38f0b2c025f3` / tree `be555e3b8a2c6334abfa58c674ea8d61f8193002` 实施。没有使用旧工作区覆盖远程，也没有改动 C 色板或删减最终地图。

## 实施阶段

1. **构建机生成预览。** `bake:residential` 保留真实住宅规划强制重算和客户端输入校验/实时回退，并输出 `src/generated/greyPreview.ts`。预览地形由真实高度场降采样，公路由实际曲线/宽度采样；地标使用最终真实包围盒，普通建筑及住宅在合批前捕获真实包围盒。生成文件随代码版本构建，不依赖客户端先构建城市。修改地形、设施或布局后运行 `npm run build` 同时刷新两类数据。
2. **独立灰模首屏。** scene → loadingPreview → 两次 rAF 等待 → environment → city → night → focus → labels → camera → animation。预览没有地形/城市构建的静态依赖；生产产物检查同时覆盖旧初始化故障和新的轻量预览依赖。首屏使用灰色海面、低面数地形、道路带与建筑盒，关闭阴影、像素比限制为 1，直接使用正式相机与 OrbitControls。状态条不拦截地图输入，支持旋转、缩放、平移和窗口缩放；尚未就绪的工具按钮明确禁用。
3. **分片恢复。** 地形行、洞口裁切、独立地标、场地细节、接路寻路、铁路、海岸总站、地块尝试、住宅小区、住宅合批、植被尝试及实例批次设协作式检查点。累计工作约 6 ms 后使用 rAF + timer 让出绘制和输入机会；近期输入期间加长让步至 40 ms。检查点不能抢占一个尚未返回的 Three.js/Canvas 调用，6 ms 是软预算。
4. **替换和优先级。** 地标组合定位、缩放、动画根节点及拾取框一次性落位后才显示，替换对应灰盒；住宅按实时视锥及相机目标距离优先选择下一小区，最后恢复固定小区顺序合批/登记占地。道路和基础数据、地标、交通预约仍遵守原依赖顺序，没有随视野任意重排依赖。灰盒在对应正式对象加入时隐藏，完成后彻底释放全部预览几何/材质。
5. **完整功能交接。** 灯光、聚焦、标签及镜头仍在完整 city 后初始化，避免旧的车站未生成故障；因此地标拾取和标签统一在全城完成后开放。本轮没有提前部分注册交互。昼夜、动画暂停、保存布局、`?time`、`?view=assets`、`?asset`、沉浸观察和按需资产工具保持原入口；预览不重置相机。正式动画循环启动后立即取消预览循环并移除监听器，恢复阴影/像素比。构建失败时保留预览及已完成内容，给出重新加载按钮，不在可能半初始化的模块上盲目重入。
